# Integrity Audit Log — PSI Threshold Validation

**Date**: 2026-10-18
**Triggered by**: post-analysis review identifying five integrity issues.
**Effect on pre-registered verdict**: none. The pre-registered verdict
(`verdict.json`, UNDERPOWERED) stands unchanged. The issues below affect
how v2 and the positive interpretation of v1 results must be qualified.

---

## Issue 1 — Post-hoc false-alarm metric redefinition

**Finding**: After observing that T=1.8% produces FA/hr=5.69 under the
pre-registered per-alert count, the analysis text in REPORT.md and
experiment_log.md proposed switching to a per-event FA count and claimed
the confirmation gate "partially addresses" the high FA rate.

**Problem**: Changing the FA metric after seeing the outcome is a post-hoc
modification of the pass criterion. The pre-registered rule counts alerts.

**Action taken**:
- REPORT.md scope statement: replaced the per-event redefinition paragraph
  with a plain statement that the gate was not evaluated and cannot be
  claimed to address FA rate.
- experiment_log.md: replaced the "switching from per-alert to per-event
  criterion" sentence with "pre-registered verdict is NOT_SUPPORTED, no
  post-hoc redefinition applied".

**Affected files**: REPORT.md, experiment_log.md.

## Issue 2 — Test sessions used twice

**Finding**: The test split (data/test.csv + data/validation.csv) was first
used in the v1 analysis (verdict.json, 2026-10-18) to evaluate T=1.0% and
T=1.8% on the cgroup avg10 signal. The v2 analysis then re-used the same
test split to evaluate the Prometheus deriv signal.

**Problem**: The test data is no longer held out. v2 test results cannot
constitute a formal verdict.

**Action taken**:
- `verdict_v2.json`: added fields `test_data_status: EXPLORATORY_ONLY`,
  `verdict_status: EXPLORATORY_ONLY`, `verdict_formal: INVALID_TEST_DATA_ALREADY_USED`.
  The original `verdict` field was renamed to `verdict_exploratory_point_estimate`.
- REPORT.md Test 4 heading changed to "Exploratory evaluation only". Added
  explicit warning that test data was already used in v1.

**Affected files**: verdict_v2.json, REPORT.md.

## Issue 3 — AUC=1.0 is a structural artifact, not a quality result

**Finding**: Test 1 (signal sanity) reported AUC=1.0 and declared the
stop condition "not triggered". Investigation shows:

- Pearson correlation between `psi_some_avg10` and `latency_ms` in
  train.csv: **0.9994**.
- Both columns were generated by the same synthetic model
  (generate-large-dataset.py, deriv Prometheus query maps to psi_some_avg10;
  the workload generator produces latency_ms from the same simulation).
- Shuffled AUC (1000 within-series permutations, seed=0):
  mean=0.569, std=0.004. Observed AUC is 104.8 sigma above shuffled mean.
  This confirms co-generation, not separability.
- Per-series AUC: 0.9999 in all 6 series — no series deviates.
- Positive rows (latency > 120.68 ms): 4560 (22.0%). Negative: 16176 (78.0%).

**Problem**: The AUC does not measure signal quality; it measures how
strongly the two co-generated columns are correlated. The sanity test
result is not interpretable as an information-theoretic check.

**Decision**: Test 1 status = **FAILED** (structural artifact).
The stop condition (AUC < 0.55) was formally not triggered, but the
test is invalid on this dataset. Calibration and v2 exploratory results
stand as computed, but all downstream claims about signal informativeness
based on AUC=1.0 are retracted.

**Action taken**:
- `verdict_v2.json`: added `test1_auc_status: FAILED` and
  `test1_auc_failure_reason` with the above numbers.
- REPORT.md Test 1 section rewritten to state FAILED, include all
  diagnostic numbers, and explain the consequence.

**Affected files**: verdict_v2.json, REPORT.md.

## Issue 5 — Unsupported confirmation-gate claim

**Finding**: REPORT.md scope statement (v2 section) originally contained:
"the confirmation gate (two consecutive predictions within 60 s) partially
addresses this — see confirmation_gate.py. That gate's effectiveness on
this dataset is not evaluated here."

**Problem**:
1. The gate operates on model predictions (q90 from make_prediction()), not
   on the raw PSI signal. The current make_prediction() is a placeholder
   (q90 = current * 1.3), not real TFT inference.
2. No test was run on the gate. Claiming it "partially addresses" the FA
   problem is unsupported.
3. The pre-registered FA metric counts alerts. A per-confirmation-event
   definition would require a new pre-registration and fresh test data.

**Action taken**:
- REPORT.md scope statement: paragraph replaced with a plain note that
  the gate was not evaluated and cannot be claimed to address FA rate.
- No claim about the gate is made anywhere in the report.

**Affected files**: REPORT.md.
